### 档位定位：深读（`deep`）

深读档交付一份**能拿去复现**的报告：除了骨架各部分的常规要求，还要把训练过程、梯度回传路径和每个设计选择背后的证据强度写清。用户在控件里选它，通常是真的要动手复现、要逐节抠细节，或者上一轮的结果被他判定细节不够。

**档位由控件选定，不由你推断，也不要从请求话术里反推**；按本档交付，用户的口吻像在要更轻的东西时，在导读里说一句可以换档即可。

### 篇幅与交付文件名

| 项 | 值 |
|---|---|
| 正文篇幅 | 通常 8000 字以上（不算报告头、图注、术语表）——**参考值，不设上限** |
| 文件名 | `<简称>-深读报告.md` |
| 位置 | 当前工作目录 |

`<简称>` 用标题里一眼能认出的短名（如 `SHINE`、`ViT`），不要用 PDF 文件名；报告头里仍写论文全称。

**篇幅来自细节与证据，不是来自重复。** 宁可在附录细节上多写几百字，也不要靠车轱辘话凑数。反过来，**字数不是本档的验收标准**：真正的标准是 §3 的三条额外要求（训练过程、梯度回传、证据强度）逐条兑现；为了凑到 8000 字而灌水，比写得短更糟。论文本身信息量不足以支撑这么长时，如实交付并在导读里说明即可，不要编细节填篇幅。

### 读到什么程度

**一次 `workflow` 调用，并行分节读全文 + 附录**；主智能体自己只读摘要与引言。

| 谁读 | 读什么 |
|---|---|
| 主智能体 | `paper_read` 读第 1 页摘要与 1–2 页引言，拿地图与元信息 |
| 分节子智能体（3–6 个） | 正文**每一节都要被覆盖**（节数超出上限就按相近主题合并），各回结构化笔记（claims / numbers / mechanism / missing） |
| 训练与实现细节子智能体（1–2 个） | 附录的**超参表、梯度与损失定义、算力与数据配比、消融设置**，回同一套笔记 |
| 图表子智能体（1 个） | 跑 `paper_figures`、逐张 `read_image`，回「图号 → 这张图在说什么 → 支撑哪条主张 → 裁切是否可用」，并附**图注原文**与「裁切框里有没有混进图注文字」 |
| 主智能体 | 跨节对比、术语一致性等笔记没覆盖的，用 `paper_search` 补，**不要凭印象补** |

- 子智能体的 prompt 必须自包含：它看不到本会话，`docId`、页码、章节标题要写进 prompt。
- 附录没有相关细节时写「论文未附相关细节」，不要替论文补。

### 报告骨架里哪几节要加深

七部分标题与顺序固定；§3、§4、§5 是本档的重点。

| 部分 | 本档写法 |
|---|---|
| 1 一句话总结 | 按骨架 |
| 2 问题与背景 | 写清前人三种妥协分别是什么、各自为什么不够 |
| 3 核心方法 | 在骨架 §3 之上**必须再写三条**：① **训练过程逐步走一遍**——哪些参数可训练、哪些被冻结，损失由哪几项组成、各在哪一步算出来；② **梯度怎么回传**——从损失到生成出的权重、再回到超网络参数，中间经过哪些张量、哪几段是冻结的骨干网络；③ **每个设计选择的证据强度**——论文用图/表/消融支持它，还是只给了一句定性说法，后者要点名 |
| 4 实验与证据 | 同骨架，另外把消融逐项对照写清；成本口径把一次性开销与摊销后的推理开销分开写；复现风险（代码与权重是否公开、超参是否给全、有无闭源组件）逐项交代 |
| 5 可靠性评估 | 四层分开写，「未验证」写全，不只挑最要命的几条 |
| 6 贡献与局限 | 论文承认的局限与你看出来的局限分开写，后者标明是你看出来的 |
| 7 术语表 | 收报告里用到、读者可能卡住的关键术语，仍不是术语大全 |

§3 的第 ② 条最容易写空：论文没说清的地方写「论文未交代」，再给出你的推断并标明是推断。

### 执行流程

1. `paper_import` 导入；元信息以首页正文为准。
2. `paper_read` 读摘要与引言（约 2 次工具调用，不必更多）。
3. 起一次 `workflow`：分节子智能体覆盖正文每一节，**同一 workflow 里并行起训练与实现细节子智能体、图表子智能体**；三者用同一套笔记 schema，prompt 各自自包含。
4. 成稿写入 `<简称>-深读报告.md`；训练过程与梯度回传的信息必须有笔记支撑，笔记没有的用 `paper_search` 回原文找，仍找不到就写「论文未交代」并把自己的推断单独标出。图插在第一次提到它的段落紧后面，**图注原文写在图片下方、不要出现在 PNG 里**。
5. 核对：起一个**数字核对子智能体**（prompt 带 `docId` 与成稿数字清单，逐条回原文比对，列出对不上的项）；主智能体用 `skill` 加载 `paper-verify` 自审，重点看 §3 的三条额外要求是否逐条兑现。
6. 改完阻断项后 `present` 交付，并给一段简短导读：做了什么、最值得注意的一点、你对可靠性的判断；写明这是深读档，不要复述报告目录。
