# 已知限制

都是实测出来的边界，不是猜测。改动前请先确认这些取舍还成立；其中几条是刻意的取舍，见
[设计与取舍](design.md)。

## 首次导入有解析成本

`paper_import` 会把每页解析**两遍**：第一遍只统计全篇正文基准字号（标题判定要用），第二遍才抽正文
与结构化块。本机实测（Node v24.21.0，本地 SSD）：

| 论文 | 页数 | 首次导入 | 再次导入（命中缓存） |
|---|---|---|---|
| 普通论文 | 17 | 127ms | 2.3ms |
| 图表较多 | 31 | 247ms | 3.4ms |

同一份文件之后都命中缓存，不再重新解析。这是**本机实测值**，磁盘与 CPU 不同会有差异，只作量级参考。

## 缓存只增不减

源 PDF 副本与渲染出的 PNG 都会留下，同一页不同 dpi 各存一份（`figures/p002@120.png` 与
`figures/p002@300.png` 是两个文件；同页同 dpi 命中缓存，不会重复渲染）。这是刻意的取舍：锚点要可
复现，缓存就必须自包含。要腾空间得人工处理，插件不写任何清理逻辑。

## PDF 内嵌标题/作者经常是错的或没有

工具把它作为参考返回，并提示以正文首页为准。实测导入的两篇论文里，`meta.json` 根本没有这两个字段
（缺失时字段整个不出现，而不是给空串）。

## 章节锚点的粒度取决于论文模板

判定要求标题「加粗」或「大于全篇正文基准字号」，这是为了不把表格行误判成标题。多数模板
（NeurIPS / CVPR / arXiv 的 `\section` 与 `\subsection`）两者都满足；但 ICLR 的 `\subsection` 是与
正文同号的**小型大写**，于是像 ViT 那种论文只能标到 `§5`，标不到 `§5.1`。这是刻意的取舍：漏判只是
锚点变粗，误判会让锚点指向错误的章节。实测三篇论文（Attention / ResNet / ViT）的检出结果分别是
24 / 13 / 5 个标题，没有假锚点。①

## `window` 档的上下文是拼起来的

`paper_search` 默认的 `window` 档会把命中块与相邻块用空格接起来（约 700 字符），因此返回的片段可能
跨越语义边界（例如命中段落的最后一句与下一节的标题连在一起）。需要精确到某一句时用
`context: "block"`；命中项里带的是**命中块**的锚点，拼接进来的相邻块可能与锚点不同节。

## 公式的上下标会丢，本工具不做公式 OCR

纯文本抽取拿不到数学排版：论文里的 `d_model^{-0.5}` 会抽成 `d_model−0.5`，读起来像减法。本工具
**不集成公式识别模型**（Nougat / MinerU / pix2tex / Mathpix 之类都要额外的模型或外部服务，与本包
「只有 mupdf 与 yaml 两个依赖」的取舍冲突）。取而代之的是一条规范加一道核对：

- 报告里的公式一律写成 LaTeX（行内 `$...$`，独立成行用 `$$` 独占一行的块，因为 DSH 的 Markdown
  渲染只认这种写法）；
- 写之前必须用 `paper_figure` 渲染那一页、`read_image` 看过原文，再自己写成 LaTeX；
- 上下标确实看不清时就写清语义（「模型维度的 −0.5 次方」）并注明未能确认，**不许猜着补 `^{}`**。

代价是这一步依赖模型愿不愿意去看原页；`paper-verify` 会把「用纯文本或代码块贴公式」「公式里混
Unicode 上下标」列为阻断项，但没有核对过的 `^{}` 在文本层面看不出来——只能靠抽查原页发现。

## 图注只按形态识别

判据是「`Figure` / `Fig.` / `Table` + 编号 + 紧跟冒号或句点」，外加把紧贴其下的续行接回来。因此：

- 模板里写成 `Figure 3 The architecture`（编号后不跟冒号或句点）的图注认不出来——但放宽成「编号后
  可以什么都没有」会让正文里的 `Figure 7 visualizes …` 也变成图注（实测 SHINE 上多认 6 个假图注，
  它们又去挤相邻图注的可用空间）；
- 页面上没有形态匹配的图注时 `captions` 是空数组，工具会如实说明，而不是让模型去猜哪段文字是图注；
- 认不出图注的图，其裁切框也就没有「图注边界」可用——这类图仍可能带进正文行（但不含图注文字，
  因为图注压根没被识别成块）。

## 图形区域检测是启发式的

`paper_figures` 用「显示列表候选 + 图注所在栏与侧 + 墨迹收紧」推裁切矩形（设计与踩过的坑见
[设计与取舍](design.md#图形区域是按图注找出来的)）。它是启发式，下面这些情形会漏或会多框：

| 情形 | 结果 | 怎么办 |
|---|---|---|
| 图注比图窄、图却跨栏 | 只框到一栏 | 用 `paper_figure` 传 `bbox` 手动裁 |
| 图注与图分别在两页 | 判为 `undetected` | 同上 |
| 纯文字表格、没有矢量图元 | 靠墨迹与「每行字符数」推，可能带进相邻正文 | 同上，或干脆把表格转成 Markdown 表 |
| 图在页面最顶端、论文又没有页眉 | 整栏宽的文字行可能被当成页眉削掉 | 同上 |
| 图的内容是一整页位图 | 会框住整页 | 属于「本来就没有可裁的边界」 |

自动裁不出来的项不会静默消失：`paper_figures` 会把它们连同原因一起列在 `undetected` 里。技能要求
每张放进报告的图先 `read_image` 看一眼，就是为了在交付前发现裁歪的情况。

唯一硬保证的是「图上不含图注文字」：渲染前会按该页图注块的 bbox 削掉重叠部分，`paper_figure` 的
手动 bbox 也一样。副作用是**故意想裁图注本身**时会被拒（剩余不足 8pt 会直接报错）——要看图注就用
`paper_read` 读那一页的正文，或传 `avoidCaptions: false` 明确表示要连图注一起裁。

## 论文地图有上限

`paper_import` 返回的章节树最多 60 条、图表清单最多 40 条、每条图注截断到 140 字符，超出的部分
以 `omittedSections` / `omittedFigures` 报数。这是给模型当索引用，不是完整清单——需要完整图表清单时
用 `paper_figures`（它不受这个上限约束，只受自己的 `max` 约束）。

## `paper_figures` 单次最多 24 个

`max` 限定 1–64，默认 24。论文图表多时用 `pages` 分批。这是为了避免一次调用渲染几十张图、把
工具结果撑爆。

## 首次检测有渲染成本

`paper_figures` 第一次跑要为每个带图注的页面渲染一次（100 dpi）求墨迹分布，再走一遍 display list；
每个裁出来的图还要按目标 dpi 渲染一次。SHINE（31 页、29 个图表，默认 `max: 24`）本机实测：
检测约 0.42 s，检测 + 裁图合计约 1.3 s，再次调用检测命中缓存（`reused: true`）但**裁图会重渲染**，
合计约 0.95 s。

裁图不做缓存是刻意的：`paper_figure` 的手动裁切允许同一个 `label` 配不同的 `bbox`，按文件名复用会
返回上一次的区域，那种错误肉眼很难发现。用 `pages` 限定范围、或调小 `max`，都能直接省掉这部分开销。

## 宽松匹配的片段不落在命中词上

短语命中时，返回的片段从命中位置开始；退化成「所有词都出现」的宽松匹配时，片段从**块首**固定的
字符窗口开始。所以宽松模式下片段里可能看不到你搜的那个词。结果里会标明这次是宽松匹配，看到这个
标记就该把整段读出来核对，而不是只信片段。②

## 参数范围只在代码里

`paper_search` 的 `limit` 限定 1–30（默认 6）、`context` 只认三个档位、
`paper_figure` 的 `dpi` 限定 36–600 且单次 ≤ 8 页、`paper_figures` 的 `dpi` 同样 36–600 而 `max`
限定 1–64（默认 24）、`paper_read` 的 `maxChars` 必须为正。这些范围来自代码校验——schema 不支持
`minimum` / `maximum`，`enum` 虽然能写进 schema，但校验闭包是手写的，也得自己补。所以模型无法从
工具描述里读出边界，只能撞到报错；报错信息会写清合法范围。③

## 平台分派来自 preset

`presets/paper.patch.yml` 里 bash / pwsh 两行按 `process.platform` 互相 `disabled`，与官方
`preset-standard` 的写法一致，所以本插件在 Windows 与 Linux 上都能用；但 preset 的这份分派是
宿主平台相关的，跨平台改 preset 时要连带检查。本插件自身（`lib/`）没有平台分支。

## 五个工具曾经在别的模式下也出现在工具表里（已修）

第一版把模型可见面挂在 profile 根层（因为浏览器半部的档位控件只能由根层 bundle 提供，原因见
[设计与取舍](design.md#档位控件为什么挂在profile-根层)），于是 `paper_import` / `paper_search` /
`paper_read` / `paper_figure` / `paper_figures` 在 standard 等模式的工具表里也能看到。

现在本包被**挂两次**：根层那一行（`role: control`）只负责让控件进页面并注册档位端点，五个工具与
三个技能随 `role: agent` 那一行回到 preset 的 scope 层。实测（探针逐 agent 读工具表与技能目录）：

| 视角 | `paper_*` 工具 | 本插件技能 |
|---|---|---|
| 论文解读模式的 agent | 5 | 3 |
| standard 模式的 agent | 0 | 0 |
| standard → 切到论文解读 | 5 | 3 |
| 论文解读 → 切到 standard | 0 | 0 |
| 全局视角（`schemas()` 不带 scope） | 0 | 0 |

代价是**这个包在两个地方各有一行，且都不能删**：删掉根层那行控件不进页面，删掉 preset 那行技能与
工具整体消失。两行都由本包自己的 patch 提供，`role` 写错或缺失会直接报错（不猜默认值）。

## 档位控件只认会话投影里的 agentPreset

控件读的是会话投影的 `agentPreset`（`projectionValues.agentPreset`）。如果某个部署没有装配
`@deepseek-ai/dsh-agent-preset-registry`，或者会话还没写入选定事件，控件就当作「不是本模式」而
不渲染。这是刻意的：宁可控件不出现，也不要在一个别的模式里留下可写的档位。

判断**不读创建时的 `header.agentPreset`**：两者可能不一致。实测本机三条论文会话的 header 都写着
`standard`，其中两条的日志里有 `agent-preset/selected = paper`（用户在首个 turn 之前用模式选择器
换过档）——按 header 判会把这几个会话的档位控件一起废掉。

端点这一侧同时认 **live 会话**（投影直接读）与**冷会话**（`sessionQuery.observeSession` 读一次
持久化日志算同一个投影）。后者是必需的：Web 里点开一条历史会话看记录不会激活 Agent
（`history.page` 的 *without activating an Agent*），只认 live 会话会让「回到旧会话」时报
「档位读取失败」。代价是点开一条旧会话时多一次日志读（按 stat 修订号缓存在 observation 层）。

模型可见面**不依赖这个判断**：技能与工具挂在 preset 的 scope 层上，隔离由 DSH 的 scope 链给出，
与控件读到什么无关。`lib/preset-gate.js` 只在档位端点上用（控制面，端点 URL 可猜测，所以逐请求校验）。

## 档位文件不随会话归档清理

`$DSH_HOME/paper-reader/levels.json` 里的记录只增不删：会话结束后那条 `sessionId -> 档位` 仍然留着。
文件很小（每条几十字节），取舍是「不做清理逻辑」；要清就人工删这个文件，删掉只会让所有会话回到
默认的「解读」档。

## `--dump-config-schema` 不能用

`dsh --profile web --dump-config-schema` 会以 `unrecognized Loader tree carrier` 退出 1。这是 DSH 对
preset 行的既有局限，在不含本插件的基线 profile 上就能复现，与本插件无关；该命令不能用来验证本插件
的加载。验证请用[开发文档](development.md#验证-bundle-与-preset-组装)里的 `--dump-config` 方法。
