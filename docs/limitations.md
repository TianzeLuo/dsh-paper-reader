# 已知限制

都是实测出来的边界，不是猜测。改动前请先确认这些取舍还成立；其中几条是刻意的取舍，见
[设计与取舍](design.md)。

## 首次导入有解析成本

`paper_import` 会把每页解析**两遍**：第一遍只统计全篇正文基准字号（标题判定要用），第二遍才抽正文
与结构化块。本机实测（Node v24.21.0，本地 SSD）：

| 论文 | 页数 | 首次导入 | 再次导入（命中缓存） |
|---|---|---|---|
| 普通论文 | 17 | 127ms | 2.3ms |
| 图表较多 | 31 | 247ms | 3.4ms |

同一份文件之后都命中缓存，不再重新解析。这是**本机实测值**，磁盘与 CPU 不同会有差异，只作量级参考。

## 缓存只增不减

源 PDF 副本与渲染出的 PNG 都会留下，同一页不同 dpi 各存一份（`figures/p002@120.png` 与
`figures/p002@300.png` 是两个文件；同页同 dpi 命中缓存，不会重复渲染）。这是刻意的取舍：锚点要可
复现，缓存就必须自包含。要腾空间得人工处理，插件不写任何清理逻辑。

## PDF 内嵌标题/作者经常是错的或没有

工具把它作为参考返回，并提示以正文首页为准。实测导入的两篇论文里，`meta.json` 根本没有这两个字段
（缺失时字段整个不出现，而不是给空串）。

## 章节锚点的粒度取决于论文模板

判定要求标题「加粗」或「大于全篇正文基准字号」，这是为了不把表格行误判成标题。多数模板
（NeurIPS / CVPR / arXiv 的 `\section` 与 `\subsection`）两者都满足；但 ICLR 的 `\subsection` 是与
正文同号的**小型大写**，于是像 ViT 那种论文只能标到 `§5`，标不到 `§5.1`。这是刻意的取舍：漏判只是
锚点变粗，误判会让锚点指向错误的章节。实测三篇论文（Attention / ResNet / ViT）的检出结果分别是
24 / 13 / 5 个标题，没有假锚点。①

## 公式的上下标会丢

纯文本抽取拿不到数学排版：论文里的 `d_model^{-0.5}` 会抽成 `d_model−0.5`，读起来像减法。所以本模式
的规范要求引用公式前先用 `paper_figure` 渲染那一页、`read_image` 看过原文；没核对过就必须在稿子里
注明「上下标未能从纯文本确认」。

## 图注只按形态识别

`Figure 3:` / `Fig. 2.` / `Table 1 ` 这类前缀；页面上没有这种前缀时 `captions` 是空数组，工具会如实
说明「本页没找到形态匹配的图注」，而不是让模型去猜哪段文字是图注。

## 宽松匹配的片段不落在命中词上

短语命中时，返回的片段从命中位置开始；退化成「所有词都出现」的宽松匹配时，片段从**块首**固定的
字符窗口开始。所以宽松模式下片段里可能看不到你搜的那个词。结果里会标明这次是宽松匹配，看到这个
标记就该把整段读出来核对，而不是只信片段。②

## 参数范围只在代码里

`paper_search` 的 `limit` 限定 1–30、`paper_figure` 的 `dpi` 限定 36–600 且单次 ≤ 8 页、
`paper_read` 的 `maxChars` 必须为正。这些范围来自代码校验——schema 不支持 `minimum` / `maximum`，
所以模型无法从工具描述里读出边界，只能撞到报错。报错信息会写清合法范围。③

## 平台分派来自 preset

`presets/paper.patch.yml` 里 bash / pwsh 两行按 `process.platform` 互相 `disabled`，与官方
`preset-standard` 的写法一致，所以本插件在 Windows 与 Linux 上都能用；但 preset 的这份分派是
宿主平台相关的，跨平台改 preset 时要连带检查。本插件自身（`lib/`）没有平台分支。

## `--dump-config-schema` 不能用

`dsh --profile web --dump-config-schema` 会以 `unrecognized Loader tree carrier` 退出 1。这是 DSH 对
preset 行的既有局限，在不含本插件的基线 profile 上就能复现，与本插件无关；该命令不能用来验证本插件
的加载。验证请用[开发文档](development.md#验证-bundle-与-preset-组装)里的 `--dump-config` 方法。

---

① 这三组数字与本机解析耗时都需要真实论文才能复现，仓库里只有手写合成的三页 fixture，因此无法从
仓库内重建；它们是当时在本机的实测记录。

② 实现位置：`lib/pdf.js` 的 `searchPaper` 在 non-phrase 分支把片段起点传给 `at >= 0 ? at : 0`。

③ 实现位置：`lib/tools.js` 里四个工具的 `execute`；范围常量没有抽成命名常量，改范围时记得连着
schema 描述与 persona 措辞一起看。
