# 论文解读报告

产出两个东西：一份 Markdown 报告文件，以及在对话里给一段简短导读。

报告的目标读者是**不懂这个方向、但愿意认真读**的人。判断标准很简单：读完能自己复述这篇论文在做什么、凭什么、边界在哪。

## 导入，拿地图

先 `paper_import` 拿 `docId` 与**论文地图**（章节树 + 图表清单），再 `paper_read` 读摘要与引言。地图是后面所有动作的索引：它能告诉你论文有哪几节、各在哪几页、哪几页有图表，**不要从摘要开始顺序通读**。

确认元信息：标题、作者、发表处、年份。以论文首页正文为准，不要用文件名猜，也不要用 PDF 内嵌元数据——它经常是空的或者写错的。

建立锚点习惯：每写一个论断，手边要有它的出处页码。写不出来源的内容就不要写。定位依据用 `paper_search`，不要靠印象翻页。

## 报告骨架

七个部分，标题和顺序固定。**不要增删**，也不要合并——固定结构是为了让不同论文的报告可以横向对照。档位只决定每部分写多深（具体哪些部分要加深见上面的档位一节）。

### 报告头（必须有）

```
**论文**：<标题>
**作者**：<作者>
**发表**：<会议/期刊 年份；有 arXiv 编号就写上>
**原文**：<paper_import 返回的 sourcePath>
**docId**：<docId>（缓存目录 <cacheDir>）
```

**原文与 docId 必须写**——读者据此 `paper_import` 同一份文件，锚点才对得上。论文给了代码或项目地址也一并写上。

### 1. 一句话总结

一到两句，说明这篇论文**具体做了什么**、结论是什么。

不要写「本文提出了一种高效的方法」这类空壳句式——它没有传递任何信息。要写成「用 X 换掉了 Y，在 Z 上把指标从 A 提到 B」这种能验证的形态。

总结里用到的指标（FID、PSNR、准确率……）如果这是它第一次出现，按 §3 的要求就地解释一句它在算什么；解释不了就不要拿它当结论的支点。

### 2. 问题与背景

- 论文要解决的具体问题（不是「某领域很重要」这种泛论）
- 已有方法卡在哪里
- 论文自己如何描述贡献

### 3. 核心方法

这一节是报告的主体，也是最容易写坏的地方。

- **先解释概念，再给形式化定义**。术语首现写「中文名（English term）」并紧跟一句白话解释。
- **把「它在算什么」讲出来，而不是只给名字**：评价指标说清比较什么、往哪边变算好；论文自造的损失项说清惩罚／奖励什么行为；借用的概念说清在本文指什么。
- **同一指标的不同口径要分开**（gFID / rFID / iFID、FID / FID-50k、准确率 / F1），并说明本文用哪一种、能否与别处的数字直接比。
- **用一个具体的小例子把机制走通**。例子必须产生中间状态、一路走到输出；只给一个表面类比不算。
- **公式写成 LaTeX**（行内 `$...$`，独立成行 `$$` 独占一行），逐个符号解释含义与取值范围。
- 说清关键设计选择，以及**为什么这么选**（论文通常给了动机，找不到就说明找不到）。

深读档的额外要求见档位一节。

### 4. 实验与证据

按「观察 → 它支持什么主张」的链条写，**不要并列罗列结果**。对每个主要主张说明：

- 论文用什么实验或定理支持它（带锚点）
- 对比基线是什么
- 证据到哪一步为止

**AI 方向论文逐条覆盖这张清单**，论文没报告的写「论文未报告」——空白本身就是读者需要知道的信息：

| 项 | 要交代什么 |
|---|---|
| 骨干模型 | 型号与规模（参数量/层数/上下文长度），权重从哪来 |
| 训练数据 | 规模、来源、配比；与评测集是否有重叠 |
| 算力与时长 | GPU 型号×张数、步数或时长、有无省显存手段（梯度检查点、混合精度） |
| 评测协议 | 基线是否同数据、同算力、同参数量；指标口径（F1 / EM / PPL / Accuracy 不能混说） |
| 稳定性 | 单次结果还是多次平均；有没有随机种子与方差 |
| 成本口径 | 一次性开销与摊销后的推理开销分开写；显存与吞吐是实测还是解析估算 |
| 消融 | 哪个设计选择单独做了对照，结论到什么程度 |
| 复现风险 | 代码与权重是否公开、超参是否给全、有没有依赖闭源组件 |

非 AI 方向的论文按它的领域惯例换成对应的可比项，但「论文没报告什么」这一点必须保留。

### 5. 可靠性评估

按四层分别写，不要混在一起：

| 层次 | 写什么 |
|---|---|
| 作者主张 | 论文自己声称的结论 |
| 直接证据 | 论文给出的实验结果、定理、数据（带锚点）|
| 报告推断 | 你根据内容推出的（**必须写明这是推断**）|
| 未验证 | 论文没有验证、或验证不充分的环节 |

这一节的价值在于让读者一眼看出哪些结论可以直接引用、哪些要自己复核。

### 6. 贡献与局限

- **作者声称的贡献 vs 实际成立的贡献**。两者的差距本身是重要信息。
- 局限性分两类写：论文自己承认的，以及你从证据边界看出来的（后者标明是你看出来的）。
- 适用边界：什么条件下这个方法不成立。

### 7. 术语表

表格三列：术语 | 中文名（English）| 一句话解释。

只收报告里真正用到、且读者可能卡住的关键术语——**不是术语大全**。报告正文里已经解释过的简单词不必重复收。

## 图表：裁好、看过、放在第一次提到的位置

**不要用整页截图，也不要把图堆在报告末尾。图片里不许出现图注文字。**

1. 导入后调一次 `paper_figures`，把图与表按图注自动裁出来。报告要用图就传 `outputDir`，指向报告同级的资源目录（例如 `./<论文简称>_figures`）——**不要引用缓存目录里的路径**，缓存随时可能被清掉，报告要能单独发出去。
2. **每张要放进报告的图，先用 `read_image` 看一眼。** 自动裁切是启发式的：可能带进正文行，也可能漏掉坐标轴标签。裁得不对就用 `paper_figure` 传 `bbox`（`"x0,y0,x1,y1"`，PDF 点）手动裁，再复核一次。看不见图就别放图，改为转述图注并标注「未查看图像，仅转述图注」。
3. **图注不是图的一部分**：它作为文字排在报告里图片的下方，**不能出现在 PNG 里**。两个裁图工具都会返回「图注原文」，用那段文字即可。
   - 手工传 `bbox` 时如果框到了图注，工具会把框自动收紧到图注之外，并在返回值里列出被排除的图注——这是预期行为，不要为了让图带上图注再放大 bbox。
   - 图看过后若发现画面底部残留半行说明文字，按返回的收紧结果重裁，或把 `bbox` 的下边界上移。**「图里带半行图注」属于阻断项。**
4. 在**第一次提到该图的段落紧后面**插图，图片下方用一行斜体给出图注原文（长的截到一两句，但不要截到只剩半句）与锚点：

   ```markdown
   ……论文用四个面板分别报告重建与补全的困惑度 [p.7 Fig.5]。

   ![Figure 5：重建与补全的困惑度（均值、中位数与 P10/P90 分位带）](SHINE_figures/fig5_p007@200.png)

   *Figure 5. Pretraining Results: Reconstruction and completion. [p.7 Fig.5]*
   ```

5. 同一段提到多张图就依次插在那一处。**报告末尾不再放截图汇总**；只有正文确实没提到、但读者需要看的图，才归到「附：图表清单」里，并说明为什么放这里。
6. 图放进报告是为了让读者看清趋势或结构，**图的解读写在正文里**（先说明看这张图要回答什么，再写观察，最后写推断与边界），图片本身不承担论证。

## 写作规范

以下四条是系统提示之外的报告特有要求：

- **锚点密度**：第 3、4、5 部分几乎每段都应有锚点。锚点页用 `[p.7]`，章节用 `[p.7 §3.2]`，图表用 `[p.5 Fig.2]`。
- **不写评价性空话**。「这项工作意义重大」「为后续研究奠定了基础」这类句子删掉不影响任何信息量。
- **公式写成 LaTeX**（行内 `$...$`，独立成行时 `$$` 独占一行）；写之前先 `paper_figure` + `read_image` 核对原页——纯文本抽取会丢上下标，看不清就注明「上下标未能从原文确认」，**不要猜着补 `^{}`**。

## 交付

1. 把报告写成一个 Markdown 文件，文件名按档位一节给的那样，放在当前工作目录下。
2. 用 `present` 把该文件声明为交付物。
3. 在对话里给一段简短导读：这篇论文做了什么、最值得注意的一点、以及你对它可靠性的判断。**导读不要复述报告目录**，并说明本次用的是哪一档（用档位一节里的名字）。

## 写完后自审

报告成稿后，用 `skill` 加载 `paper-verify` 跑一遍再交付——它机械地查术语、指标是否说清「在算什么」、公式是否 LaTeX、锚点、推断标注、数字还原与插图这几类自己读容易漏的问题，并按当前档位核对文件名、读取范围与各节重心。
