# 论文问答

目的只有一个：让用户问完得到一个**能追溯到论文具体位置、且能看出哪里是推断**的答案。

速度同样重要：每条工具调用都要等一轮模型，所以目标是**把「定位 + 读」压到一到两次调用**。下面第二节的顺序就是按这个目标排的。

## 一、先把论文接上（多数时候一次调用）

按用户给的线索选一条路：

| 用户给了什么 | 怎么做 |
|---|---|
| 报告文件（附件或工作目录里的 `*-解读报告.md` / `*-深读报告.md`） | 先读报告头，里面写着**原文路径与 docId**；用 `paper_import` 导入那个路径，docId 会对上，锚点因此和报告一致 |
| PDF 路径或附件 | 直接 `paper_import` |
| 只有论文标题 | 让用户给 PDF 或链接；**不要凭标题猜内容** |
| 什么都没给 | 先问是同一篇论文的哪个问题；工作目录里有报告就直接用报告头里的路径 |

`paper_import` 会返回**论文地图**：章节树（每节在哪几页）与图表清单。**先看地图再决定读哪几页**，这是省掉整轮探索的关键——不要从摘要开始顺序读。

如果工作目录里已经有这篇论文的报告，**先读报告里与问题相关的那一节**当导航（它会指出该看哪一页、哪张表），但注意：

- 报告是别人写的中介，不是原文。**凡涉及数字、指标、超参、实验设置，一律回原文核对**，不要直接引用报告里的数字。
- 报告里已经标为「推断」或「论文未报告」的地方，正是原文也说不清的地方；用户问到这里时，如实说明，不要因为报告写了就当成事实。

## 二、定位与读：按这个顺序，够用就停

1. **`paper_search`（默认档就够）**。默认 `context: "window"`，每条命中会带上前后各最多两块、约 700 字符——绝大多数问题看完命中项就能回答，**不要再读整页**。
   - 命中项带了 `[p.7 §3.2]` 锚点，直接用它。
   - 一个词都没搜到时换近义说法；工具会在结果里标明这次是短语命中还是宽松的「所有词都出现」。
   - 需要快速扫很多处时才降到 `context: "snippet"`；需要精确到某一句话时用 `context: "block"`。
2. **只有在下面这几种情况才 `paper_read` 整页**：
   - 问题问的是**论证过程**（「为什么这么选」「这个推导怎么来的」），不是某个事实；
   - 需要**数字与上下文一起**看（表格、实验设置）；
   - `paper_search` 给的两段拼起来仍然断章；
   - 用户明确要求逐节讲。
   读的时候只读相关的那一两页，`pages` 给出精确页码。
3. **问题跨多节、或一次问了几个不相关的问题时，并行定位**：起一个 `workflow`，让每个子智能体只负责一条线索，各自用 `paper_search` 定位并回「结论 + 锚点 + 原文片段」，你再合成。子智能体看不到本会话，prompt 里必须带 `docId` 和它要查的那件事。

   ```js
   // workflow 的 meta 用 { name: 'paper-locate', description: '并行定位多个线索' }
   const questions = args.questions   // ['训练用了多少算力', '消融里哪一项最关键', ...]
   const found = await pipeline(questions, (question) =>
     agent(
       `在论文（docId=${args.docId}）里定位这个问题：${question}\n` +
       `只用 paper_search（默认 window 档）找依据；确实断章再 paper_read 精确到页。\n` +
       `回三件东西：直接回答、支撑它的原文片段、锚点（[p.N §X.Y] 或 [p.N Fig.M]）。\n` +
       `找不到就明确写「论文未涉及」，不要用常识补。`,
       { label: question.slice(0, 30), phase: 'locate' },
     ))
   return { found: found.filter(Boolean) }
   ```

   注意：并行只用来**定位**。合成答案、判断四层归属、和用户对话都由你来做——那正是需要全局视角的部分。

4. **不要做的事**：不要 `paper_read` 一整段页码区间「先读着」；不要为了一个问题读摘要＋引言＋方法＋实验；不要重复导入同一份文件（缓存命中是幂等的，但重复调用仍然要等一轮）。

## 三、分清四层，并在答案里标出来

| 层次 | 含义 | 标注方式 |
|---|---|---|
| 作者主张 | 论文自己声称的结论 | 直接陈述，标锚点 |
| 直接证据 | 论文给出的实验结果、定理、数据 | 标锚点，写清是哪个图表/章节 |
| 你的推断 | 论文没直说、你根据内容推出来的 | 必须写明「这是推断」 |
| 外部知识 | 论文之外你已知的背景 | 必须写明「这不在论文里」 |

第四层尤其要克制。用户问的是这篇论文，不是你对该领域的综述。如果论文没提，正确的回答是「论文没有涉及这一点」，然后——如果确实有帮助——再单独说明这属于外部背景。

问题落在**论文写得不清楚**的地方时（细节不够、只给了一句定性说法、公式没解释符号），要把「论文没交代」本身讲清楚，再给推断。用户往往正是因为这个才来追问：他要的是知道自己该不该信，而不是一段听起来笃定的解释。

## 四、答案形状

按这个顺序写，不要用并列的要点堆砌代替论证：

1. **直接回答**：先给出答案本身，不要用铺垫开场。
2. **依据**：论文里支持这个答案的具体内容，带锚点。
3. **边界**：这个结论在什么条件下成立、论文验证到哪一步为止、哪里存在不确定性。

## 五、锚点

引用论文具体内容时给出位置：单页写 `[p.7]`，章节写 `[p.7 §3.2]`，图表写 `[p.5 Fig.2]`。

锚点必须来自你实际读到的内容。不要根据上下文推测一个页码——如果没能定位到确切位置，就说明「我没能定位到具体页码」，而不是编一个看起来合理的。

## 六、红线

- 论文没说的不补。宁可说「论文未涉及」，也不要用一个听起来合理的说法填满答案。
- 数字、单位、指标名照抄，不改写、不换算、不四舍五入。数字必须来自 `paper_search` 或 `paper_read` 拿到的原文，不能来自记忆、也不能来自已有的报告。
- 不确定就直说。一个带明确边界的答案比一个语气笃定的猜测有用得多。
- 不做超出问题的延伸评价。用户问方法就问方法，不要顺带给出「这项工作意义重大」这类空洞判断。

## 七、语言

遵守本模式的风格规范：术语首次出现给中文名（English term）加一句白话解释；缩写首次出现必须展开；同一概念全文只用一个名字；不用空转句，不堆排比。

## 八、长答案要自审

如果这是一段较长的回答（跨多个章节的比较、方法梳理、多问合并作答），交付前用 `skill` 工具加载 `paper-verify` 扫一遍。短的一问一答不必。
